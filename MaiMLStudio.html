1. システム概要と基本操作

アプリケーションの目的

MaiML Studioは、計測分析データ共通フォーマット「MaiML」のデータ構造を視覚的に構築・管理するためのツールです。 XMLの直接編集における複雑さを排除し、GUIベースで以下のデータ構造を定義します。

  • Document Metadata: プロジェクトや文書の基本情報
  • Methods (Protocols): 複数の実験手段をタブで管理（ペトリネット、テンプレート、データ）
  • Templates: データのスキーマ定義（型、単位、記述）
  • Data & Events: 実際の測定データと実行履歴（イベントログ）

グローバルメニューバー

テーマ切替ライトモード/ダークモードを切り替えます。OSの設定を初期値として反映します。
プロジェクト保存 (JSON)編集中の状態をJSONファイルとして保存します。後で再編集が可能です。
プロジェクト読込 (JSON)保存したJSONファイルを読み込み、状態を復元します。
MaiML出力 (XML)MaiML標準規格に準拠したXMLファイルを生成・ダウンロードします。

メソッド（実験プロトコル）の管理

1つのプロジェクト内で複数の実験・分析メソッドをタブ形式で管理できます。 ヘッダー下のタブバーを使って以下の操作が可能です。

  • 追加 (+): 新しい空のメソッドを作成します。
  • 切り替え: タブをクリックして編集対象のメソッドを切り替えます。
  • メニュー (▼): タブの右側のアイコンから、メソッド名の変更、複製、削除が行えます。
Proxy Place (参照場所): あるメソッドから別のメソッドのデータを参照する場合、「Import Place」機能を使用して、他メソッドのPlaceを読み取り専用（Proxy）として取り込むことができます。
メソッド名の重複不可: メソッド名はプロジェクト内で一意である必要があります。既存のメソッド名と同じ名前は作成できません。また、新規追加時のデフォルト名は既存の名前と重複しない連番が自動的に割り当てられます。

2. 文書情報定義 (Document Metadata)

MaiMLファイルのヘッダー情報にあたる部分です。データのトレーサビリティを確保するための重要なメタデータを管理します。

General Information & Properties

文書ID、UUID、名称等を設定します。UUIDはボタン一つで自動生成可能です。

Tips: Global Propertiesでは、string, int, float, dateTime, uri などの型を指定して、文書全体に関わる属性（プロジェクトコード等）を追加できます。

アクター定義 (Vendors / Instruments / Owners / Creators)

データ生成に関与する組織、装置、所有者、作成者を定義します。

  • Vendors: 装置メーカーや試薬供給元などを登録します。
  • Instruments: 使用した分析機器を登録します。
  • Creators: データの作成者（研究者）を登録します。
参照関係の構築 (References) Creatorsの登録時には、既に登録済みの Vendor や Instrument をプルダウンから選択して紐付けることができます。これにより、「誰が・どの装置を使って」作成したかという内部リンクが構築されます。

3. プロセス設計 (Petri Net Design)

実験・分析のワークフローを「ペトリネット」としてグラフィカルに設計します。ここで定義したPlace（場所/状態）が、次のステップでのデータテンプレートの紐付け先となります。

  • TemplateRef: テンプレート継承（青破線）
  • InstanceRef: インスタンス継承（緑破線）
  • Import External Place: 他メソッドのPlaceと継承関係を結ぶために読取専用(EXT)で取込

操作方法

  • 移動 (Pan): キャンバス背景を左クリックドラッグ
  • 拡大縮小: マウスホイール
  • 削除: ノード選択後にDeleteボタン

Arc / Ref の接続操作

Arc・TemplateRef・InstanceRef はいずれも同じドラッグ＆ドロップ操作で接続します。

  1. ツールパレットで接続種別（Arc / TemplateRef / InstanceRef）を選択
  2. 始点ノードをドラッグ開始（オレンジ/青/緑の枠でハイライト）
  3. マウスに追従する破線プレビューを確認しながら終点ノードへドラッグ
  4. 終点ノード上でマウスを離すと接続確定（有効ターゲットは緑枠、無効は赤枠）

Arc: Place ↔ Transition 間のみ接続可能（実線矢印）

TemplateRef (青色破線・上弧): Place → Place。テンプレート同士の継承関係

InstanceRef (緑色破線・下弧): Place → Place。インスタンス同士の継承関係

Overview タブ（俯瞰図）

メソッドタブバー右端の 🐦 Overview タブをクリックすると、全メソッドを俯瞰した構成図を表示します。

  • 全メソッドのPlace・Transition・Arcを縮小表示し、メソッド名付きの境界ボックスで区切ります
  • メソッドをまたぐ TemplateRef（青破線・上弧）/ InstanceRef（緑破線・下弧）を接続線で表示します
  • 左クリックドラッグでパン、マウスホイールでズームができます
  • Overviewは閲覧専用です。編集はメソッドタブをクリックしてキャンバスに戻って行います

Step 1 テンプレートの種類の選択

各Placeに対して、以下の3種類から役割を選択して追加します。

Material
試料・入力

Step 2 プロパティとコンテンツの定義

項目 説明 主なデータ型
Properties メタデータ（単一の値）。名前、ID、設定値など。 stringType, intType, floatType, propertyListType (ネスト用)
Contents 主要データ（配列も可）。スペクトルデータ、時系列ログなど。 contentStringListType, contentFloatListType...

Excelインポート機能

手動入力の代わりに、Excelファイルから一括で定義を読み込めます。対象のExcelファイルには、Placeと同じシート名が必要です。 Key列に>記号を使ってネスト構造を表現できます。

Element Key Type Units Description Value Size Axis ScaleFactor FormatString
property Temperature propertyListType 温度設定
property >Set_Temp doubleType °C 設定温度 180
property >Control propertyListType 制御パラメータ
property >>PID_P doubleType P値 1.2
content >>Time_Log contentDoubleListType s 時間記録 0 10 20 3 t 0.00
property Operator stringType 担当者 Tanaka

ネスト構造のルール: Key列の先頭に>記号を付けることでネストレベルを表現します。>=1階層、>>=2階層。 親要素は必ずpropertyListTypeである必要があります。

並び順の規定: 各階層レベルごとに、propertyを先に記述し、その後にcontentを記述してください。 例: ルートレベルで property → content の順、ネストした子要素グループ内でも property → content の順。 親レベルに戻れば、再び property から記述可能です。

6. XML暗号化機能

概要

MaiML規格 (JIS K0200) に準拠したXML暗号化機能です。property要素やcontent要素を選択的に秘匿できます。

暗号化アルゴリズムAES-256-GCM（認証付き暗号化・改ざん検知内蔵）
鍵導出PBKDF2-SHA256（反復回数 100,000 回）
暗号化方式コンテンツ暗号化（Type=#Content）— 親要素タグ・属性はそのまま残し、子要素のみ暗号化。UPA違反なし。
準拠仕様W3C XML Encryption 1.1 / JIS K0200
⚠️ 注意：パスワードを忘れると復号できません。安全な場所に保管してください。

暗号化の手順

  1. Templates タブまたは Data タブで、暗号化したい property / content 行の右端にある アイコンをクリックします。
  2. アイコンが （アンバー色）に変わると「暗号化対象」としてマークされます。再クリックで解除できます。
  3. 通常通り MaiML出力 (XML) ボタンをクリックします。
  4. 暗号化パスワードの設定ダイアログが表示されます。4文字以上のパスワードを2回入力して確認します。
  5. 出力されたMaiMLファイル内で、対象要素の子要素が <xenc:EncryptedData> に置き換えられます。

暗号化対象の指定箇所

Templates タブ

テンプレートの property / content 行。ここで設定した暗号化フラグはインスタンスにも引き継がれます。

Data タブ（継承プロパティ）

テンプレートから継承した property / content 行に個別で暗号化を設定できます。

Data タブ（追加フィールド）

インスタンスに独自追加した instanceProperty / instanceContent 行。

ネスト構造の暗号化

propertyListType の親要素を暗号化すると、子の property / content / uncertainty もまとめて暗号化されます。

7. ファイル連携機能 <chain>

概要

MaiML規格 (JIS K0200) の <chain> 要素を使ったファイル連携機能です。複数のMaiMLファイルを関連付け、改ざん検知（ハッシュ値による整合性確認）を実現します。ブロックチェーンのように「このファイルは別のファイルの内容を受け継いでいる」という時系列の連鎖を記録できます。

ユースケース例： 試料合成(A) → 前処理(B) → 計測(C) という一連の実験工程において、C が B と A を参照・継承していることを記録する。
ハッシュ方式SHA-256（ファイル全体のバイト列。署名付きファイルは <ds:DigestValue> を使用）
出力位置<document> 要素内の <date> 要素の直後
key属性規定値は key="chain"

登録手順

  1. Document Metadata タブの一番下にある Chained Files セクションを表示します。
  2. Add Chain ボタンをクリックし、連携先の .maiml ファイルを選択します。
  3. 選択したファイルの //document/uuid 値と SHA-256 ハッシュ値が自動的に取得・表示されます。
  4. 通常通り Export MaiML ボタンをクリックすると、<chain> 要素がMaiMLファイルに書き出されます。

出力されるXML例

<document id="...">
  ...
  <date>2025-06-01T10:00:00+09:00</date>
  <chain id="chain_001" key="chain">
    <uuid>0bce8354-55f1-4047-b221-988e00c87c79</uuid>
    <hash method="SHA-256">B1sDhiK3...</hash>
  </chain>
</document>

MaiML Viewer での確認

関連するMaiMLファイルを MaiML Viewer に複数同時ロードすると：

  • ファイル間の連鎖が 橙色の破線矢印（🔗 chain）でグラフ上に表示されます。
  • Document Metadata パネルにハッシュ検証結果が表示されます（✅ Chain verified / ❌ Hash mismatch / ⚠️ Linked file not loaded）。

8. MaiMLファイルの生成

データのエクスポート

全ての入力が完了したら、ヘッダー右上の [Export MaiML] ボタンをクリックしてください。 以下の構造を持つ単一のXMLファイルが生成されます。

<maiml ...>

</maiml>

1. System Overview & Basic Operations

Purpose of Application

MaiML Studio is a tool for visually constructing and managing the "MaiML" (Measurement Analysis Instrument Markup Language) data structure. It eliminates the complexity of direct XML editing and allows defining the following data structures via GUI:

  • Document Metadata: Project and document information.
  • Methods (Protocols): Multiple experimental workflows management.
  • Templates: Data schema definitions (types, units, descriptions).
  • Data & Events: Actual measurement data and execution logs.

Global Menu Bar

Toggle Theme Switches between light and dark modes. OS settings are reflected as the default.
Save Project (JSON) Saves the editing state as a JSON file. It can be re-edited later.
Load Project (JSON) Reads a saved JSON file and restores the state.
Export MaiML (XML) Generates and downloads an XML file compliant with the MaiML standard.

Method (Protocol) Management

You can manage multiple experimental/analysis methods within a single project using tabs. Use the tab bar below the header to perform the following operations:

  • Add (+): Create a new empty method.
  • Switch: Click tabs to switch the active method being edited.
  • Menu (▼): Use the icon on the right of the tab to Rename, Clone, or Delete the method.
Proxy Place: To reference data from another method, use the "Import Place" feature to include a Place from another method as a read-only (Proxy) Place.
Unique Method Names Required: Method names must be unique within a project. Duplicate names are not allowed. When adding a new method, the default name is automatically assigned the next available number to avoid conflicts.

2. Document Metadata

This corresponds to the header information of the MaiML file. It manages important metadata for ensuring data traceability.

General Information & Properties

Set the Document ID, UUID, Name, etc. UUID can be automatically generated with a single button.

Tips: In Global Properties, you can specify types such as string, int, float, dateTime, and uri to add attributes related to the entire document (e.g., project code).

Actor Definition (Vendors / Instruments / Owners / Creators)

Define the organizations, instruments, owners, and creators involved in data generation.

  • Vendors: Register instrument manufacturers, reagent suppliers, etc.
  • Instruments: Register the analytical instruments used.
  • Creators: Register the data creators (researchers).
Building References When registering Creators, you can link them to already registered Vendors or Instruments from the pull-down menu. This builds internal links indicating "who used which instrument" to create the data.

Excel Import / Export

Instead of manual entry, you can bulk-load definitions from an Excel file using the Import Excel button on each template card. Use the Export Excel button next to it to download the current template as an Excel file. The Excel file must contain a sheet named exactly after the corresponding Place. Use > symbols in the Key column to represent nested structures.

Element Key Type Units Description Value Size Axis ScaleFactor FormatString
property Temperature propertyListType Temperature Settings
property >Set_Temp doubleType °C Set Temperature 180 0.00
property >Control propertyListType Control Parameters
property >>PID_P doubleType P Gain 1.2
content >>Time_Log contentDoubleListType s Time sequence 0 10 20 3 t 0.00
property Operator stringType Operator Name Tanaka

Columns A–F are common to all elements. Size (xs:int, content only): number of data points. Axis (xs:string, content only): axis label (e.g. "x", "t"). ScaleFactor (xs:double): scale multiplier. FormatString (xs:string): display format (e.g. "0.00"). Columns G–J are optional — leave blank if not needed. Older 6-column files remain fully compatible.

Nested Structure: Use > at the beginning of the Key. >=depth 1, >>=depth 2. Parent elements must be propertyListType.

Order Rule: Within each nesting level, list property elements before content elements.

Export Excel: The exported file contains two sheets — the template sheet (named after the Place) and a dataType一覧 reference sheet listing all available types.

6. XML Encryption

Overview

Selective encryption of property and content elements, compliant with JIS K0200.

AlgorithmAES-256-GCM (Authenticated Encryption with built-in tamper detection)
Key DerivationPBKDF2-SHA256 (100,000 iterations)
Encryption TypeContent Encryption (Type=#Content) — parent tag and attributes remain intact; only child elements are encrypted. No UPA violation.
ComplianceW3C XML Encryption 1.1 / JIS K0200
⚠️ Note: If you forget the password, decryption is impossible. Keep it in a safe place.

How to Encrypt

  1. In the Templates or Data tab, click the icon at the right end of the property / content row you want to encrypt.
  2. The icon turns amber to mark it as an encryption target. Click again to deselect.
  3. Click the MaiML Export (XML) button as usual.
  4. A password dialog will appear. Enter a password (4+ characters) and confirm it.
  5. In the exported MaiML file, the child elements of the target are replaced with <xenc:EncryptedData>.

Where to Mark Encryption Targets

Templates Tab

Property / content rows in templates. The encryption flag is inherited by instances.

Data Tab (Inherited fields)

Property / content rows inherited from templates can be individually marked.

Data Tab (Additional fields)

instanceProperty / instanceContent rows added directly to an instance.

Nested Structures

Encrypting a propertyListType parent encrypts all child property / content / uncertainty elements together.

7. File Chaining <chain>

Overview

File chaining using the <chain> element of JIS K0200. Links multiple MaiML files together and enables tamper detection via hash verification. Like a blockchain, it records the temporal chain of inheritance — "this file is derived from another."

Example use case: In an experiment sequence — Synthesis (A) → Pre-processing (B) → Measurement (C) — file C records that it references and inherits from B and A.
Hash methodSHA-256 (full file byte stream; for signed files, uses <ds:DigestValue>)
Output positionImmediately after the <date> element inside <document>
key attributeDefault value: key="chain"

How to Register a Chain

  1. Open the Document Metadata tab and scroll to the Chained Files section at the bottom.
  2. Click Add Chain and select the target .maiml file to link.
  3. The //document/uuid value and SHA-256 hash are automatically extracted and displayed.
  4. Click Export MaiML as usual — the <chain> element will be included in the output file.

Output XML Example

<document id="...">
  ...
  <date>2025-06-01T10:00:00+09:00</date>
  <chain id="chain_001" key="chain">
    <uuid>0bce8354-55f1-4047-b221-988e00c87c79</uuid>
    <hash method="SHA-256">B1sDhiK3...</hash>
  </chain>
</document>

Viewing in MaiML Viewer

When loading multiple related MaiML files simultaneously into MaiML Viewer:

  • Chain relationships are visualized as orange dashed arrows (🔗 chain) on the graph.
  • Hash verification results appear in the Document Metadata panel (✅ Chain verified / ❌ Hash mismatch / ⚠️ Linked file not loaded).
